# The TASM originals

Nothing in here is needed to build or run anything. It is kept for two
reasons, and you can ignore it for a third.

**It is the original.** These are the sources as they were first written,
assembled with Borland's Turbo Assembler — the tool this project was built
with from the start, before the toolchain moved to something that could be
handed to a reader.

**It is the proof.** Each of these has a twin under `GAMES/` or `EXAMPLES/`,
translated for [flat assembler](https://flatassembler.net/). The only way to
answer *"did the behaviour change?"* is to compare against the binary this one
produced — which is why the **`.COM` files are archived here too**, and why
`TOOLS/BinAccount` compares binaries rather than sources. That comparison is
what caught ten 386 jumps in a WIRE CITY build that looked finished.

**And you do not need it.** Turbo Assembler is commercial software that cannot
be included here, so unless you already own it, nothing in this folder will
assemble on your machine. The versions under `GAMES/` will — the assembler for
those is in `TOOLS/FASM/`, in this repository, free to use.

## Building them anyway, if you have TASM

There is no longer a build path in the repository for these. The orchestrator
that drove TASM inside DOSBox was retired when the last program migrated, and
keeping a build for sources nobody can assemble would have been a fiction —
`TASM.EXE` and `TLINK.EXE` cannot be shipped here.

Each folder keeps the `BUILD.BAT` it was built with. They expect TASM and
TLINK on the path and the shared modules at `..\ENGINE\`, which is where they
now are. That is enough to rebuild any of this on a machine that owns the
tools, and it is deliberately the only thing offered.

| `TRAINER/` | the flight school |
| `WIRECITY/` | the wireframe night-flight |

**That is everything.** The migration is finished, and this folder is closed:
nothing else is coming, and nothing here is edited again. Each program's live
source is in its own folder outside `TASM/`, and it is the one that is worked
on from now on.

Every binary these produced is archived beside its source, because that is
what `TOOLS/BinAccount` compares — the sources here cannot be reassembled
without owning TASM, and the binaries do not care.

Projects arrived here **after** their FASM translation was verified, never
before. While a translation was in progress both versions sat side by side in
the program's own folder, the FASM one generated by `TOOLS/Tasm2Fasm` and not
hand-edited until it was proven.

## Why the two builds differ in size

WIRECITY is 5552 bytes from TASM and 5240 from FASM, and that is correct.
TASM is a one-pass assembler: its `JUMPS` directive reserves room for a near
jump, and when a short one turns out to be enough it pads the leftovers with
`NOP`, because the addresses after it have already been placed and cannot
move. FASM makes three passes and needs no padding.

All 312 bytes of the difference are those NOPs. Nothing else differs — and
*that* is the test the migration had to pass: not that the files match, but
that every byte of the difference can be explained. `TOOLS/BinAccount` is what
does the explaining, instruction by instruction, and it stops at anything it
cannot name.

These frozen sources earn their keep by being the thing to compare against.
An earlier FASM build of WIRECITY was 5230 bytes and looked right; the ten
missing bytes were ten conditional jumps FASM had encoded in the 386 long
form, because `.8086` has no FASM equivalent and the restriction was lost in
translation. Without a TASM build to compare against, nothing would have
noticed.
