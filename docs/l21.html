LESSON 15 — THE GROUND STOPS BEING FLAT

click the black screen first to grab the keyboard · this lesson wants a real keyboard — you are here to fly it and then to change it · back to the arcade
Type MAKE, then RUN. Space takes off. Arrows fly it — down is nose up. H is the one to press.

H · HIDDEN LINES

One byte for each of the 320 screen columns. Press it and the far half of the picture stops being a fishing net. Press it again and it goes back. That is the whole lesson in one key.

F · TWO ENGINES

The patched line against the classic one — and while H is on, F does nothing at all, because the hiding routine is the only line in the program that knows the array exists.

DOWN · NOSE UP

Not a bug. It is a control column and you pull it towards you to climb. And you cannot fly through a hill: 96 units of clearance above whatever is underneath you, read off the same cache the picture is drawn from.

ESC · LAND

Then EDIT RELIEF.ASM. VEXAG is the one number in the file that is not the game's, and changing it changes the whole flight.

WHY THE GROUND LOOKED FLAT, AND WHY ONE SHIFT FIXED IT

The island has been in memory since lesson 0x11. Every node of the lattice takes a byte from it and turns it into a height, with the game's own sum:

h = (H - 88) * 5
if h > 560 then h = h + (h - 560)     ; the slope doubles up there

Work three bytes through it. 120 gives 160. 200 gives 560. 255 — the highest the map ever goes — gives 835, which is over the line, so add the difference back and you have 1110. Now put that beside the other number in the program: the nodes are 1024 units apart. The tallest thing on the whole island is barely taller than one step of the grid is wide. It was not a bug, it was arithmetic, and it is exactly what it looked like.

So the program lies, in one instruction. VEXAG doubles the height and touches nothing else. It is the only number in the file that is not the game's own, and it is the difference between a landscape you fly over and one you fly between.

A WIREFRAME HAS NO FRONT AND NO BACK

The moment the ground has a shape, a hill can be in the way of what is behind it — and nothing in the program knows that. The near-plane clip throws away what is behind your head. The line clipper throws away what is off the edge of the screen. A ridge four miles away that comes straight through the hill in front of it is neither: it is on the screen and perfectly legal. It is simply behind something, and 64000 bytes in a row do not record that.

THE FLOATING HORIZON, IN 320 BYTES

Keep one byte for every column of the screen: the height of the highest thing drawn in that column so far. Draw the squares from the eye outwards. A pixel shows if it is above the skyline in its own column, and then it becomes the skyline. That is all of it:

if (y < HOR[x]) {        /* above the skyline: visible */
    plot;
    HOR[x] = y;          /* and it IS the skyline now  */
}

Remember that y grows downward, so above is a smaller number. Walk one column through by hand and it comes out like this. HOR starts at 200, the bottom row, so the first thing to arrive always shows:

arrives attestresult
y = 138138 < 200draw — HOR becomes 138
y = 151151 is not < 138hidden, nothing written
y = 122122 < 138draw — HOR becomes 122
y = 130130 is not < 122hidden

Drawing from the eye outwards is the other half of it, and it is a table built once at the boot. The squares are sorted by the square of their distance from the middle, because comparing squares puts them in the same order as comparing distances and costs no square root: 3 across and 4 up gives 9 + 16 = 25, and the real distance is 5.

WHAT IT COSTS, AND THE ANSWER IS NOT THE ONE YOU EXPECT

Measured on this program with the retrace wait taken off, the island seeded to a fixed value and the aeroplane parked, so all three rows draw the same picture:

see through, the patched line of lesson 876 frames a second
hidden, the skyline60
see through, the classic line (F)53

Read the last two rows again. 60 against 53: the hiding is faster. A pixel it throws out is a pixel it never writes, so the skyline does not cost anything at all — it saves. The 16 frames went somewhere else entirely: the moment the lesson wrote its own line routine it left lesson 8's behind, the one that writes its step sizes into its own instructions. The price of hiding was paid in lesson 8's coin, which is a very different sentence from "hiding is expensive".

And the counter in the running program will not say 60. It says 35. A frame that waits for the beam takes a whole number of retraces, so the only rates this machine has are 70, 35 and 23. Sixty is under seventy, so it costs two. Press H and watch it fall in one step.

AND THEN IT COMES STRAIGHT BACK OUT

This is the one routine in the course that is not in OWL FLY and never was. It is here because it is worth seeing once and worth having in your hand. It loses for a reason that is a better lesson than the algorithm: the array holds one skyline per column. A height field has exactly one. A house with a gap under it has two, and from that moment the array is lying. Fill the ground instead and the far ridge is hidden by the near one for nothing at all — the paint covers it. You do not pay for hiding, you get it with the colour.

CHANGE SOMETHING

The assembler is in the tab with you, which is the point of this page rather than a video of it:

MAKE
RUN

VEXAG is 1, which doubles the height. Try 0 for the game's own ground and see what the lesson is complaining about; try 2 and fly through a canyon. NR is 12 and is how far you can see — 13 costs you half the frame rate, not a twelfth of it, and the comment beside it says why. Reload the page and everything is back as it was, so there is nothing you can break.
