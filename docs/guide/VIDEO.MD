# VIDEO - the cards and modes: VGA 13h, CGA, EGA, MCGA, Hercules, text

Putting a picture on screen: mode 13h and its back buffer, the retrace,
the DAC, text on a graphics screen, detecting the card, and one renderer
feeding every card through a converter. Working code, in
A:\GAMES\OWLFLY3\SRC: VIDEO.INC (BLIT, WAITV), VID.INC (menu, modes,
converters), UI.INC (UBLIT, APPLYPALF).

## Rules you must not break

- Draw everything into one 320x200x256 back buffer in RAM; only the copy
  out knows the card. Anything written to A000h directly or after the copy
  (BIOS text, a status line) never reaches a converted card: on CGA, EGA
  and Hercules a healthy boot then looks hung.
- Never wait on port 3DAh on a Hercules: there is none, the floating port
  reads FFh and "wait while bit 3 is set" spins for ever.
- Never stream a 256-colour palette in a CGA or EGA mode on a VGA: those
  modes take their colours from the same DAC, and the stream overwrites
  them (the grey sky was palette entry 0). Gate it on the card.
- Ask the machine before offering a card: graphics sent to B000h on a VGA
  is a blinking cursor over an invisible game.
- Never set mode 3 on a mono machine (it boots in mode 7). To clear a text
  screen re-enter DOS's mode: INT 10h AH=0Fh, then AH=0 with that AL. Mode
  3 on exit is fine (a mono BIOS maps it to 7); Esc returns to DOS.

## Mode 13h, the default

- `mov ax,13h / int 10h`: one byte a pixel at A000:y*320+x, 64000 bytes,
  70 Hz. MCGA's 256-colour mode IS 13h. y*320 = (y SHL 8) + (y SHL 6).
- With ES = A000h and a 16-bit DI, a stray plot stays inside the video
  segment: it spoils the picture, never the code (A:\LESSONS\L13\ARM.ASM).
- On a CRT (and DOSBox's "fill" and "monitor" pictures) a pixel is about
  1.2 times taller than wide: scale screen y by SQUASH = 213 (5/6: imul,
  then /256) for round circles (A:\LESSONS\L06\CLOCK.ASM). The site's
  default "sharp" picture shows pixels SQUARE (16:10): there such a circle
  looks a little flat [DOSBOX].
- Wipe-and-redraw on the screen itself depends on speed: at DOSBox's slow
  default a lesson showed only its bottom rows. Use a back buffer (64000
  bytes = 0FA0h paragraphs, placement in the memory topic) or pin the speed
  (`config -set "cpu cycles=fixed 30000"`). Clear = `rep stosw` of 32000
  words; the copy:

```
BLIT:   push ds
        mov  ax,[bufseg]
        mov  ds,ax              ; DS:SI = back buffer
        mov  ax,0A000h
        mov  es,ax              ; ES:DI = the screen
        xor  si,si
        xor  di,di
        mov  cx,32000           ; words
        cld
        rep  movsw
        pop  ds
        ret
```

- Clear, cockpit-art copy and blit each cost about 0.1 s on an 8 MHz
  8086; effects are pennies beside them. Skip the clear when sky and
  ground repaint every pixel. Fill by words: on an 8088 `rep stosw` is
  about 7 clocks a byte, `rep stosb` 10.

## The retrace

- 3DAh bit 3 = vertical retrace (CGA, EGA, VGA). Wait out the one running,
  then wait for the next, so a call costs exactly one frame:

```
WAITV:  mov  dx,3DAh
.w1:    in   al,dx
        test al,8
        jnz  .w1                ; finish a retrace already running
.w2:    in   al,dx
        test al,8
        jz   .w2                ; the next one begins
        ret
```

- Wait right BEFORE the copy and copy at once. A wait after the copy only
  caps the rate (70, 35, 23 fps steps) and the next copy starts wherever
  the beam is.
- Hercules (status at 3BAh, another bit): return at once; mono shows no
  visible tear.
- Time the renderer without the wait: with it, CLIP.COM read 10 ticks per
  20 frames, exactly two retraces a frame.

## Palette and the DAC

- Index to 3C8h, then R, G, B (0..63 each) to 3C9h; the index advances
  itself. Read back: index to 3C7h, three reads of 3C9h. Setting a mode
  loads the BIOS palette, so stream yours after it (`out dx,al` in a
  `lodsb / loop`, NPAL*3 bytes; UI.INC APPLYPALF).
- Lease the entries in ranges and keep the map in one comment. OWL FLY III:
  0..30 game, 31..93 cockpit art (regenerated by the converter, nobody
  else may use them), 94 engine glow, 95/96 IFF, 108..112 legends, 120
  asphalt, 121..136 vehicles. Quantise all pictures sharing a lease in ONE
  run, or the ones left out get three shades of near-black.
- Animate by palette: rewrite DAC 94 each frame from a 4-step table keyed
  off the BIOS tick and the nozzles burn with no drawing.
- Fade by streaming `value*level SHR 3`, level 0..8, a level a tick. Two
  pictures with different palettes cannot cross-dissolve: dip to black.
- Day and night are two tables streamed by one routine; its tail also
  switches the converters' lookup banks, so the key works on every card.
- Never assume default colour meanings: in OWL FLY III entry 8 is WHITE,
  15 a green. Draw a known constant (0A5h) beside any value read off screen.
- 16-colour VGA modes: pixel -> EGA palette register -> DAC. Defaults put
  colour 6 at DAC 20 and 8..15 at DAC 56..63: recolour those at DAC c+48.
  Reading the DAC back passes while the screen stays wrong
  (A:\LESSONS\L23\INFOGR.PAS).
- No alpha: a full-screen flash replaces the picture. Flood every Nth row
  instead, N from 2 widening as the hit fades (three ticks), under the HUD.

## Text on a graphics screen

- BIOS teletype works in 13h: INT 10h AH=0Eh, AL char, BL colour, BH 0;
  cursor AH=02h (DH row, DL column). It writes video memory on an 8x8 grid,
  so converted cards never see it.
- ROM 8x8 font: INT 10h AX=1130h BH=3 -> ES:BP, 8 bytes a glyph (strictly
  0..127; BH=4 gives 128..255). Copy glyphs into the back buffer yourself.
- A font of your own is smaller: OWL FLY's 4x6 (3x5 ink, 4 px advance),
  41 glyphs 0-9 A-Z + - : % ., one byte a row, ink in the top 3 bits
  (FDRAW in A:\GAMES\OWLFLY3\SRC\HUD.INC, glyphs in RESDAT.ASM). A 56x50
  MFD holds 14 characters by 7 lines.
- Clamp a number before printing: 2000 came out "D00".

## Static art over the world

- White in the source art = transparent. Copy only opaque spans: a table
  of (offset, length) into the art, 0FFFFh ends it (HUD.INC PANELBMP); or
  inline `dw count`, then per span `dw dest, dw len` and the pixels:
  LODSW, LODSW, REP MOVSB (UI.INC SHCABDRW).
- RLE for big overlays (SYM.INC SIDEBMPF): token = 2 bits type + 6 bits
  count, count 0 = a word count follows; 00h end, 40h|n literal, 80h|n
  repeat, C0h|n skip. Played straight into the buffer, never decompressed:
  17-22 KB a screen against about 38 KB as spans.

## Text mode

- Mode 3: 80x25 at B800h, two bytes a cell (char, attribute bg*16+fg),
  160 bytes a row. Mode 7 (mono) has its text at B000h.
- Front menus run in text mode BEFORE the game hooks INT 9 and read INT 16h
  (the game's handler silences it): numbered rows, a digit takes its row,
  arrows walk a marker over offered rows, Enter takes it.

## Detecting the card

```
        push ds
        mov  ax,40h
        mov  ds,ax
        mov  ax,[63h]           ; BIOS data: active CRTC base
        pop  ds
        cmp  ax,3B4h
        je   .mono              ; mono: Hercules only
        mov  ax,1A00h
        int  10h                ; AL=1Ah: BL 7/8 VGA, 0Ah..0Ch MCGA
        ...
        mov  ah,12h
        mov  bl,10h
        int  10h                ; BL changed: EGA (a VGA answers too)
```

- CGA modes run on every colour card, 0Dh/10h on EGA or VGA, 13h on MCGA
  or VGA, 12h on VGA only. The quiz cannot tell MDA from Hercules.
- List every card, mark the absent "- NOT IN THIS MACHINE", refuse their
  keys, start on the best present; spell out "EGA 640x350 16 COLORS".
- The DOS PC's card is a setting (svga_s3 default, vgaonly, ega, cga,
  hercules, tandy); the site switches it per run (`play owlfly3 --machine
  hercules`); a .jsdos bundle fixes it in its conf.

## The seam: one renderer, many cards

- Exactly two routines copy the buffer out (BLIT, UBLIT); both do
  `cmp byte [vcard],6 / jb .cnv`: straight `rep movsw`, or a far call to
  the converter. A new card is one converter, no renderer change. Card
  codes sort converted below straight: 1 Hercules, 2 CGA, 3 EGA 10h,
  4 EGA 0Dh, 5 VGA 12h, 6 MCGA, 7 VGA.
- Convert through tables built offline against the game palette
  (A:\GAMES\OWLFLY3\SRC\VIDLUT.INC): 256 entries x 4 dither phases
  (x AND 1 + (y AND 1)*2), 512-aligned so `xor bh,1` steps the phase and
  odd rows add 512. Dither is then free: the same `xlat` as flat colour.
- Dither "solid first": a 1/4, 2/4 or 3/4 mix of two colours wins only if
  its error plus a tax (the pair's own distance/4) is under half the
  nearest solid's; a checker everywhere creeps. Distance 3dr^2+6dg^2+2db^2.
- The cockpit is RECOGNISED, not flagged: a buffer byte equal to the
  artwork's byte at that spot IS artwork and takes a colour baked offline
  per card; anything drawn over it differs and goes through the lookup.
  Per output byte, 4 match bits: all -> bake, none -> lookup, some ->
  `(bake AND m) OR (lut AND NOT m)`, m from a 16-entry table (MEXP).
- Older cards cost MORE: the 256-colour frame is converted every frame and
  a lower detail level does not shrink that. Shrink the converted area:
  OWL FLY III BOND (8088) converts the cockpit 1 frame in 8, else the window.
  Pre-shifted tables (ink already in place per pixel position) make a
  pixel XLAT + OR: 41 -> 32 code bytes per four pixels.
- Card support is not speed support: 8086-correct, but the full frame wants
  a 286/386.

## CGA, mode 4

- 320x200x4 at B800h: even rows at 0000h, odd at 2000h, 80 bytes a row,
  4 pixels a byte, leftmost in bits 7-6.
- 3D9h = 30h: palette 1 intense (black, cyan, magenta, white); 10h:
  palette 0 intense (green, red, yellow; no white). Not mode 5: its
  burst-off colours differ per emulator and monitor.
- A VGA (DOSBox svga, the browser) in mode 4 ignored 3D9h AND INT 10h
  AH=0Bh. Set attribute registers 1..3: INT 10h AX=1000h, BL register,
  BH 6-bit code 3Bh,3Dh,3Fh (cyan, magenta, white) or 3Ah,3Ch,3Eh; 0Bh is
  teal. Switch the hardware and the lookup bank together.

## EGA 0Dh and 10h, VGA 12h

- 0Dh (320x200x16) runs on any EGA; 10h (640x350x16) needs a 128K card;
  640x480 is VGA's 12h. A real EGA in 200 lines shows only the 16 RGBI colours.
- Colours via the BIOS: INT 10h AX=1002h, ES:DX = 16 registers + overscan
  of 6-bit codes. Curated: 0,8,17,11,43,31,16,42,58,20,56,7,3,36,38,63, 0.
- Per row: make the 4-bit colour row, split it into four plane rows with
  assemble-time tables (`repeat 256`), then per plane `out 3C4h` index 2
  (map mask) = 1,2,4,8 and `rep movsw`; map mask back to 0Fh at the end.
  The heaviest converter.
- From 320x200: 10h doubles the width, 2 rows into 3 (640x300 from byte
  2000, a 25-row letterbox); 12h doubles both (640x400 from byte 3200);
  0Dh one to one, 40-byte rows. No dither on EGA: 16 curated colours band.

## Hercules, 720x348 mono

- No BIOS mode: out 3BFh,1; out 3B8h,2 (graphics, video off); 6845
  registers 0..11 via 3B4h/3B5h = 35h,2Dh,2Eh,07h,5Bh,02h,57h,57h,02h,
  03h,00h,00h; wipe B000h (4000h words); out 3B8h,0Ah (video on). VSETMDF.
- Row y at B000:(y AND 3)*2000h + (y SHR 2)*90, 90 bytes, bit 7 leftmost.
  320x200 doubled in width, 2 rows into 3 (640x300), 40 dots in, 24 down.
- Mono is dither DENSITY: two dots per palette byte by a 4x4 Bayer on luma
  (77R+151G+28B) SHR 8, phase (screen row AND 3)*2 + (x AND 1); luma under
  40 black, over 215 white (lone lit dots read as dirt).

## Testing

- DOSBox `-machine cga|ega|hercules`, always `-noautoexec`, cycles 60000
  (converters pay per pixel).
- Test each retro mode twice: on its own machine type (port assumptions)
  and on svga playing it (DAC collisions; how most players run it).
- A build that forces a card must force the quiz result too, or it takes
  the real-card road and proves nothing.

## Traps

- CGA palette key dead in the browser only -> VGA ignores 3D9h -> AX=1000h.
- Ground mirrored at the top of the cockpit -> a grown far segment moved
  the back buffer over the art copied from it (memory topic).
- Striped band crawling down the screen, only from a shell -> buffers hung
  off CS without asking DOS landed in A000h -> load low, check PSP:[2].
- Black screen in DOSBox, "unreachable" in js-dos -> a stray write or a
  wild jump, not a video bug.
